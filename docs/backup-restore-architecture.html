OpenLog Engineering Reference · Architecture & Reliability Report

In-Session JSON Archive & ACID Restore Architecture

OpenLog features an in-session structured JSON archive streaming engine with decoupled manifest metadata. The architecture delivers 100% in-process backups and restores, instant O(1) archive inspection, zero application restarts, ACID transaction safety with automatic rollback, and proactive Zip-Slip defenses.

O(1) Inspect Inspection reads only lightweight manifest metadata (~500 B) without parsing timeline entries.
ACID Safe Single SQLite transaction with automatic rollback preserves existing data on any failure.
Zip-Slip Free Strict path traversal validator rejects malicious archive paths and duplicate members.
100,000+ High-capacity bounds handling over 100k media items with bounded 256 KiB streaming chunks.
Core Principles

System Architecture & Local-First Safety

Pure In-Session Lifecycle

Backups and restores run entirely within the active app session. On restore completion, notifyStoreReload() triggers in-memory Zustand stores to re-query SQLite, refreshing all timeline and search screens immediately without app restarts.

Decoupled Manifest & Payload

Package metadata lives in manifest.json (~500 B) while domain entities reside in timeline.json. This enables near-instant inspection modals and pre-flight checks without loading multi-megabyte payloads into RAM.

Defensive Boundary Limits

Input files are treated as untrusted. Archives are bound to 512 MiB total size, 2 GiB uncompressed expansion, 256 MiB per member, 64 MiB timeline JSON, and 100,000 media files.

Format Specification

Container & Payload Structure

OpenLog archives are standard PKZip files with the .openlog extension. The archive cleanly isolates metadata, canonical timeline records, and binary media assets.

Archive Container Layout

Every .openlog archive cleanly separates metadata, relational entities, and binary media assets into three member categories:

  • manifest.json — Lightweight export metadata, counts, and schema version (Deflate Level 6).
  • timeline.json — Canonical database entities (tags, entries, settings) (Deflate Level 6).
  • media/<filename> — Individual media binaries stored using ZipPassThrough to eliminate redundant CPU compression on already-compressed media.

Export Mechanism

The Streaming Export Pipeline

Exporting serializes live database records and media files into a compressed stream without buffering the entire archive into memory or blocking user navigation.

Phase 1 · Gate

Acquire Export Gate (acquireExportGate)

Creates an asynchronous synchronization barrier that pauses background media cleanup tasks, preventing any concurrent deletions while media files are being read.

Phase 2 · Snapshot

Read-Only SQLite Database Snapshot

Executes a fast read-only query using runDb to extract tags, entries, entry-tag associations, and user settings. Absolute media URIs (e.g. file:///.../media/photo.jpg) are normalized to relative filenames.

Phase 3 · Stream

Streaming Zip Compression via fflate

Constructs and compresses manifest.json and timeline.json using ZipDeflate. Streams media files in bounded 256 KiB chunks using ZipPassThrough, keeping memory consumption low (< 30 MiB) regardless of timeline size.

Phase 4 · Notify

Background Progress Notifications & Storage

Emits progress callbacks to OS notification channels ("Saving entries", "Saving files (14 of 42)"). Saves directly to the user-picked folder, purges temporary cache, and releases the export gate.

Inspection & Restore

O(1) Inspection & In-Session ACID Restore

Archive inspection is lightweight and instant, while restoration guarantees atomic all-or-nothing commits.

O(1) Stream Inspection (inspectBackupArchive)

When a user chooses an archive file to restore, inspectBackupArchive extracts and parses only manifest.json. It validates schema format, version compatibility, and entry/media counts without buffering timeline.json or media assets into memory. The inspection prompt displays in milliseconds even for massive archives.

Step 1 · Preflight

Storage Space Calculation & Free Space Verification

Calculates required space: archiveBytes + uncompressedBytes + existingTimelineBytes + 50 MiB safety buffer. Checks device storage via FileSystem.getFreeDiskStorageAsync(). If storage is insufficient, import halts before modifying disk.

Step 2 · Decompress

Defensive Streaming Unzip & Path Traversal Check

Decompresses into an isolated staging cache folder (openlog-restore-<timestamp>-<rand>). Every file path is inspected by validateArchivePath(). Path traversal (../), root slashes (/), backslashes (\), duplicate files, or oversized members are rejected immediately.

Step 3 · Validate

Strict Schema & Cross-Count Invariant Validation

Validates manifest.json via assertBackupManifest and timeline.json via assertBackupTimelineData. Enforces cross-count parity: manifest.counts.entry === timeline.entries.length and manifest.counts.tag === timeline.tags.length.

Step 4 · ACID Commit

Single SQLite ACID Transaction

Executes inside db.withTransactionAsync(): DELETE FROM entry_tags; DELETE FROM tags; DELETE FROM entries; Batch-inserts all tags, entries, entry-tag links, and settings. Executes INSERT INTO entries_fts(entries_fts) VALUES ('rebuild') to construct the search index directly from restored entries. If any error occurs during this step, SQLite automatically rolls back the entire transaction.

Step 5 · Reconcile

Media Copy & Cache Cleanup

Only after the SQLite transaction commits successfully, staged media files are copied to the live document media directory (Paths.document/media). Staging folder is immediately deleted.

Step 6 · Refresh

Reactive In-Memory Store Notification

Fires notifyStoreReload(). All active Zustand stores, query hooks, and timeline UI screens re-fetch from SQLite immediately. The user sees their restored timeline instantly with zero application restarts.

Failure Scenarios

Fault Tolerance & Recovery Matrix

The system follows a strict fail-closed, local-first doctrine: all untrusted data is validated before mutation, resource use is tightly bounded, and existing data remains 100% recoverable.

Failure Scenario Detection Mechanism System Behavior Timeline State
Truncated / Corrupt Zip fflate streaming decompressor throws CRC/format error during chunk read. Import loop halts immediately. Staging directory is wiped in finally block. Untouched Live database was never opened for mutation.
Zip Slip Path Traversal (../../etc/passwd) validateArchivePath() inspects every member name before extracting bytes. Throws "Invalid backup file: unexpected archive path." Halts stream instantly. Protected Filesystem security boundary preserved.
Future Schema Version (e.g. v2) assertBackupManifest() checks obj.version > ARCHIVE_SCHEMA_VERSION. Throws "Unsupported backup version (2). Please update OpenLog." Untouched Prevents accidental downgrade data corruption.
Oversized Member / Zip Bomb Member size checked against BACKUP_LIMITS.memberBytes (256 MiB) & total uncompressed (2 GiB). Throws expansion limit error during streaming; aborts immediately without exhausting RAM. Protected Out-of-memory crash prevented.
Tampered Manifest Counts Cross-count validation compares manifest counts against actual extracted entities and media. Throws count mismatch error before entering SQLite transaction. Untouched Desynchronized archive rejected before DB change.
Malformed Row / Missing ID assertBackupTimelineData() validates types, coordinate numbers, and required fields. Rejects data before SQL execution. No invalid rows can ever reach SQLite. Untouched Schema invariants strictly preserved.
Power Loss Mid-SQLite Insert Operating system crash or power outage during batch insertion. SQLite WAL rollback journal deterministically rolls back uncommitted transaction on next open. Self-Healing Prior timeline restored cleanly.
User Cancellation (Abort) AbortSignal checked before every chunk and loop iteration. Closes file handles, deletes partial export/import file, dismisses notifications. Clean Zero orphan files or corrupted state.
Concurrent Media Purge acquireExportGate() synchronizes with draft discard and entry deletion. Media cleanup waits until export stream completes and gate releases. Consistent Zero missing media files in backup.
Code Architecture

Module Structure & Responsibilities

src/services/backup/

  • types.ts — Canonical archive constants (ARCHIVE_FORMAT = "openlog-backup", ARCHIVE_SCHEMA_VERSION = 1, ARCHIVE_EXTENSION = ".openlog", MANIFEST_FILENAME = "manifest.json", TIMELINE_DATA_FILENAME = "timeline.json") and strict TypeScript interfaces.
  • export.ts — Streaming export pipeline, 256 KiB chunked I/O, native ISO string date tags, export gate locking, writing separate manifest.json and timeline.json.
  • import.ts — In-session ACID restore engine with storage pre-flight, Zip-Slip prevention, manifest and timeline assertions, single SQLite transaction (db.withTransactionAsync), media reconciliation, and instant store reload via notifyStoreReload().

Utility & UI Integration

  • inspect.ts — Lightweight O(1) stream inspection reading only manifest.json without loading heavy timeline entries or media into memory.
  • utils.ts — Runtime schema validations (assertBackupManifest, assertBackupTimelineData), path traversal sanitizer (validateArchivePath), filename extractors, restore storage calculator, and concurrency export gate.
  • io.ts — Native file and directory pickers with system share fallback.
  • status.ts — Observable external store with React hook (useBackupStatus) and abort controllers (cancelActiveBackup, cancelActiveRestore).
